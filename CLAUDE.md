# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Комментарии в коде, сообщения пользователю и документация в этом проекте — на русском языке. Имена классов, методов и переменных — на английском. Придерживайтесь этого разделения.

## Что это

Консольный агент, решающий задачи программирования: отправляет запрос в LLM по OpenAI-совместимому протоколу, получает вызовы инструментов, выполняет их и возвращает результат модели. Единственный инструмент — `bash`. Рассчитан на локальный сервер (LM Studio, Ollama), но работает с любым эндпоинтом `/chat/completions`.

## Команды

Все рабочие вызовы собраны в `Makefile` — используйте его, а не голые `bundle exec`. `make help` печатает список целей.

```bash
make setup                     # установка зависимостей
make                           # spec + rubocop (цель по умолчанию)
make spec                      # только тесты
make spec FILE=spec/mini_agent/agent_spec.rb      # один файл
make spec FILE=spec/mini_agent/agent_spec.rb:42   # один пример по строке
make lint                      # только линтер
make rbs                       # проверка сигнатур в sig/

make run TASK="покажи содержимое lib"             # разовый запуск
make run TASK="запусти тесты" ARGS="--model qwen3-coder"
make repl                      # интерактивный режим
make build                     # сборка гема
```

`make check` эквивалентен `rake`: `Makefile` ничего не дублирует, а только оборачивает `rake`/`rspec`/`rubocop` с правильными флагами.

Настройки читаются в порядке: **опции CLI → переменные окружения → значения по умолчанию** (`Config::DEFAULTS`). Переменные: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `MAX_TURNS`, `RETRY_COUNT`, `RETRY_DELAY`, `MAX_TOKENS`, `ALLOW_UNSAFE`, `COMMAND_TIMEOUT`.

## Архитектура

Поток управления: `exe/mini_agent` → `CLI` (разбор опций, сборка объектов) → `Agent#run` (цикл ходов) → `LLMClient#chat` ↔ `ToolRegistry#dispatch` → `Tools::Bash` → `CommandGuard` + `ProcessRunner`.

| Класс | Ответственность |
|---|---|
| `CLI` | Разбор аргументов (таблица `FLAGS`), сборка зависимостей, коды возврата |
| `Agent` | Цикл ходов: запрос → инструменты → повтор; лимит `max_turns` |
| `LLMClient` | HTTP к `/chat/completions`, повторы, разбор ответа |
| `Conversation` | История сообщений с нормализованными ключами |
| `ToolRegistry` | Реестр инструментов и диспетчеризация по имени |
| `Tools::Bash` | Схема инструмента для модели и его выполнение |
| `CommandGuard` | Денилист опасных команд и запрос подтверждения |
| `ProcessRunner` | Запуск процесса с таймаутом и принудительным убийством |
| `Prompt` | Чтение подтверждения (+ заглушки `AutoApprove`/`AutoDeny`) |
| `UI` | Весь вывод: баннеры, спиннер, результаты инструментов |
| `Config` | Настройки из опций/ENV/умолчаний |
| `Messages` | Все пользовательские строки одним модулем |
| `Color` | ANSI-раскраска |

### Решения, которые не видны из кода

- **`Agent#run` возвращает `Conversation`, а не текст.** Именно это позволяет интерактивному режиму продолжать диалог: история передаётся обратно через `conversation:` и накапливается между задачами.

- **Два независимых бюджета вывода.** `Agent::MAX_TOOL_OUTPUT` (10 000 символов) ограничивает то, что уходит **в модель** — защита контекстного окна. `UI::PREVIEW_LINES`/`PREVIEW_CHARS` ограничивают то, что видит **пользователь** — читаемость консоли. Это разные вещи; не объединяйте их.

- **`ProcessRunner` намеренно не использует `Timeout.timeout`.** Тот бросает исключение в поток, но не убивает порождённый процесс — он остаётся висеть в фоне. Здесь процесс убивается сигналом KILL явно. `stdout` и `stderr` читаются отдельными потоками: при последовательном чтении команда с большим выводом блокируется на переполненном буфере пайпа. Оба сценария покрыты тестами.

- **Внедрение зависимостей ради тестируемости.** `UI.new(tty: false)` вообще не создаёт поток спиннера; `CommandGuard` получает `prompt:` вместо обращения к `STDIN`; `ProcessRunner.new(timeout: 0.2)` даёт тест таймаута за доли секунды. Без этого три места остались бы непокрытыми. Сохраняйте инъекцию при доработках.

- **`tool_choice: "none"` в суммирующем запросе.** По достижении лимита ходов агент просит модель подвести итог. Если не запретить инструменты, модель вернёт очередной вызов, применить который уже негде, и он потеряется молча.

- **`Color` — модуль, а не refinement.** В исходном скрипте это был refinement для `String`; refinement действует лексически, только в файле с `using`, и при разбиении на файлы неприменим.

## Тесты

`bundle exec rspec` — 152 примера, ~3 секунды. HTTP стабится через **webmock**, сеть запрещена (`WebMock.disable_net_connect!`), живой LLM для тестов не нужен. `Config` принимает `env:` явно — тесты не зависят от окружения разработчика.

Тесты `ProcessRunner` запускают настоящие процессы (таймаут, убийство, вывод на 20 000 строк) — это осознанно: моки здесь не проверили бы ровно то, ради чего класс написан.

## Безопасность

`CommandGuard::DANGEROUS_PATTERNS` — денилист регулярных выражений поверх строки, которую **составляет сама модель**. Он ловит случайный `rm -rf`, `sudo`, `curl | sh` и форк-бомбу, но **песочницей не является**: переменные, кавычки, base64 обходят любой такой список. При работе с недоверенной моделью или недоверенным эндпоинтом нужна реальная изоляция (контейнер, отдельный пользователь), а не этот фильтр. Флаг `--allow-unsafe` / `ALLOW_UNSAFE=true` снижает проверку до предупреждения.
