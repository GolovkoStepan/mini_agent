# План развития

Задачи упорядочены по сложности: чем выше, тем дешевле реализация. Сделанное
отмечается галочкой и переезжает в `CHANGELOG.md` — здесь остаётся только
пометка, чтобы был виден пройденный путь.

Оценки — порядок величины, а не обязательство.

## Ближний круг (вечер работы)

- [x] **Разделить 4xx и 5xx в `LLMClient`** (2026-08-02)

  Повторяются 5xx, 408 и 429 (последний — с учётом `Retry-After`), прочие 4xx
  падают сразу. Текст ошибки берётся из `error.message`. Разбор ответа вынесен
  в `ErrorResponse`: `LLMClient` перерос лимит `Metrics/ClassLength`, и это был
  верный сигнал — задача там действительно оказалась чужая.

  Живая проверка на LM Studio (пустой `messages`, настоящий 400): 0,27 с и одна
  попытка вместо 6,3 с и трёх. Попутно выяснилось, что на несуществующую модель
  LM Studio отвечает не 404, а молча подставляет загруженную, — так что
  `--list-models` нужнее, чем казалось.

- [x] **`--list-models`** (2026-08-02)

  Список загруженных моделей с пометкой выбранной. Запрос вынесен в
  `ModelsRequest`: справочная команда без повторов — не то же самое, что диалог
  с сессией и повторами, и слияние их в одном классе снова упёрлось в
  `Metrics/ClassLength`.

  Пункт про «подсказку в тексте ошибки 404» отпал: LM Studio на незнакомую
  модель ошибку не возвращает вовсе. Зато вскрылось другое — на неверный путь
  (`base_url` без `/v1`) он отвечает **200 с полем `error` в теле**. Без
  отдельной ветки пользователь получал «поле data отсутствует»: формально
  верно и совершенно бесполезно.

- [ ] **Проектный контекст в системном промпте** (~1–2 ч)

  `Conversation` уже принимает `system_prompt:`. Читать `AGENTS.md` или
  `.mini_agent.md` из рабочего каталога и дописывать к промпту — тогда агент
  сразу знает про `make spec` и принятые в проекте соглашения вместо того,
  чтобы выяснять это серией `ls` на каждом запуске.

  Ограничить размер: файл на 50 КБ съест контекстное окно целиком.

- [ ] **Рабочий каталог: `--cwd` и честный промпт про `cd`** (~1 ч)

  `ProcessRunner` вызывает `Open3.popen3("bash", "-c", command)` без `chdir:` —
  каждая команда выполняется в новом процессе от каталога запуска агента.
  Модель делает `cd src`, следующим ходом `ls` и видит корень проекта; понять
  причину она не может и начинает либо дублировать `cd` в каждой команде, либо
  просто блуждать.

  Дешёвое и предсказуемое лечение: `chdir:` в раннере + `--cwd` для запуска в
  чужом каталоге, а в системном промпте прямо сказать, что состояние (`cd`,
  переменные окружения) между вызовами не сохраняется. Попытка вытаскивать
  итоговый каталог из bash сложнее и надёжнее не станет.

## Средний круг (полдня–день)

- [ ] **`Reline` и слэш-команды в REPL** (~0.5 дня)

  `input.gets` не даёт ни истории по стрелке вверх, ни редактирования строки.
  `Reline` есть в stdlib, инъекция `input:` при этом сохраняется.
  Заодно `/clear`, `/model`, `/tools`, `/usage` — ложатся на `Agent#interactive`.

- [ ] **Ctrl+C по уровням** (~0.5 дня)

  `CLI#start` ловит `Interrupt` на самом верху и выходит из процесса.
  Прервать одну затянувшуюся команду и остаться в REPL нельзя — а хочется
  именно этого, когда модель запустила что-то не то. Механика убийства
  процесса в `ProcessRunner` уже есть; нужен обработчик уровнем ниже: первый
  Ctrl+C отменяет текущую операцию, второй — выходит.

- [ ] **Транскрипт в файл** (`--log session.jsonl`) (~0.5 дня)

  `Conversation` живёт в памяти и умирает вместе с процессом. Когда модель
  повела себя странно, разбираться сейчас не по чему.

- [ ] **Учёт токенов** (~0.5 дня)

  В ответе `/chat/completions` есть `usage`, и он сейчас выбрасывается.
  Показывать расход по сессии; для облачного эндпоинта это ещё и деньги.

- [ ] **Стриминг ответа (SSE)** (~1 день)

  Сейчас спиннер крутится, пока модель генерирует абзац текста. С
  `stream: true` текст идёт по мере генерации — самое заметное изменение в
  ощущении от работы, особенно на локальной модели.

  Подвох: при стриминге `tool_calls` приезжают кусками, фрагменты аргументов
  надо склеивать по `index` в дельтах. `interpret` придётся разделить на
  «разбор ответа» и «накопление дельт» — правка не косметическая.

- [ ] **Политики подтверждения** (~1 день)

  Сейчас `CommandGuard` спрашивает только при срабатывании денилиста, всё
  остальное выполняется молча. Обратная политика полезнее: заведомо читающие
  команды (`ls`, `cat`, `git status`, `rg`) пропускать автоматически, про
  остальные спрашивать. `authorize?` становится сменной стратегией — `--auto`,
  `--ask`, `--allow-unsafe`.

  Денилист песочницей не является (см. `CLAUDE.md`), а allowlist уже даёт
  что-то похожее на настоящее ограничение.

## Дальний круг (несколько дней)

- [ ] **Файловые инструменты `read_file` / `write_file` / `edit_file`** (~1–2 дня)

  Сейчас модель правит файлы через heredoc в bash: многословно, ломается на
  кавычках, расходует токены. Отдельные инструменты дают точечную замену
  подстроки. `ToolRegistry` к нескольким инструментам уже готов.

- [ ] **Сохранение и продолжение сессий** (~1–2 дня)

  `Conversation#to_a` уже отдаёт готовый к сериализации массив. Даёт `--resume`
  и разбор упавших прогонов.

- [ ] **Сжатие истории вместо жёсткого `max_turns`** (~2 дня)

  Сейчас на десятом ходу агент принудительно подводит итог. Правильнее — при
  приближении к границе контекстного окна сворачивать старые ходы в резюме и
  продолжать. Снимает главное ограничение на длинные задачи.

- [ ] **Веб-поиск: `web_search` + `web_fetch`** (~2–3 дня)

  Отложено до появления сервера. Умолчание — свой SearxNG (тот же профиль, что
  у `llm-server`: своё железо, ключей нет, запросы наружу не уходят), провайдер
  за интерфейсом с одним методом `search(query)`, чтобы Brave/Tavily
  добавлялись классом на три десятка строк.

  Что придётся решить: JSON-формат в SearxNG по умолчанию выключен и
  запрос неразрешённого формата возвращает 403; лимитер режет программных
  клиентов и на приватном инстансе его выключают; число результатов через API
  не регулируется — обрезать на своей стороне.

  Отдельная и обязательная часть — `NetworkGuard`, аналог `CommandGuard` для
  URL. `web_fetch` по адресу от модели это SSRF: `169.254.169.254`,
  `localhost:1234`, `file://`. Проверять после резолва DNS и на каждом
  редиректе — иначе обходится редиректом на приватный адрес. Для агента,
  который уже ходит в локальную сеть за LLM, диапазон достижим.

- [ ] **Реальная песочница** (оценка неясна)

  `CLAUDE.md` честно говорит, что денилист песочницей не является.
  `sandbox-exec` на macOS или запуск в контейнере закрыли бы это по-настоящему.

- [ ] **MCP-клиент** (оценка неясна)

  Подключение чужих инструментов по стандартному протоколу вместо написания
  каждого руками. Самое дорогое в списке и самое рычажное.

## Отклонённое

- **Параллельное выполнение `tool_calls`.** В `Agent#run` они идут `each`, и
  три независимых чтения могли бы выполниться разом. Но подтверждения
  `CommandGuard` полезут вперемешку, а выигрыш на локальной модели теряется на
  фоне времени генерации: узкое место не здесь.
