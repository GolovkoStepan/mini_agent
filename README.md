# MiniAgent

[![CI](https://github.com/GolovkoStepan/mini_agent/actions/workflows/ci.yml/badge.svg)](https://github.com/GolovkoStepan/mini_agent/actions/workflows/ci.yml)

Минимальный кодовый агент на Ruby: получает задачу, планирует шаги, выполняет shell-команды через LLM с поддержкой tool calling и возвращает результат.

Работает с любым OpenAI-совместимым эндпоинтом `/chat/completions` — LM Studio, Ollama, vLLM или облачный провайдер.

## Установка

```bash
git clone https://github.com/GolovkoStepan/mini_agent.git
cd mini_agent
bin/setup
```

Или как гем:

```bash
gem build mini_agent.gemspec
gem install ./mini_agent-0.2.0.gem
```

### Адрес LLM-сервера

По умолчанию агент обращается к хосту `llm-server` на порту 1234. Если сервер
стоит на отдельной машине, пропишите её адрес в `/etc/hosts`:

```
192.168.1.10	llm-server
```

Если сервер запущен на той же машине — укажите петлевой адрес:

```
127.0.0.1	llm-server
```

Имя выбрано односоставным намеренно: зону `.local` на macOS перехватывает
mDNSResponder, и записи в `/etc/hosts` там срабатывают ненадёжно.

Правку `/etc/hosts` можно не делать — тогда задавайте адрес явно через
`--base-url` или `LLM_BASE_URL` (см. ниже).

## Использование

```bash
# разовая задача
mini_agent "найди все TODO в проекте и покажи их списком"

# интерактивный режим — история диалога сохраняется между задачами
mini_agent -i

# указать сервер и модель
mini_agent --base-url http://localhost:1234/v1 --model qwen3-coder "запусти тесты"
```

Из репозитория без установки гема:

```bash
bundle exec ruby -Ilib exe/mini_agent "задача"
```

### Опции

| Опция | Описание |
|---|---|
| `-i`, `--interactive` | Интерактивный режим |
| `--max-turns N` | Максимальное число ходов (по умолчанию 10) |
| `--max-tokens N` | Максимум токенов в ответе модели (по умолчанию 4096) |
| `--context-window N` | Размер контекстного окна модели в токенах |
| `--retry-count N` | Число попыток при ошибке сети (3) |
| `--retry-delay N` | Задержка между попытками в секундах (2) |
| `--base-url URL` | Адрес LLM-сервера |
| `--model NAME` | Имя модели |
| `--list-models` | Показать модели, загруженные на сервере |
| `--cwd DIR` | Рабочий каталог для команд агента |
| `--log FILE` | Писать транскрипт диалога в файл (JSONL) |
| `--[no-]allow-unsafe` | Разрешить опасные команды без подтверждения |
| `-v`, `--version` | Версия |

### Коды возврата

| Код | Что произошло |
|---|---|
| 0 | Задача выполнена |
| 1 | Ошибка употребления: неверная опция, нет задачи, несуществующий каталог |
| 2 | Не удалось открыть соединение — сервер не отвечает или адрес неверен |
| 3 | Сервер ответил отказом, и задача не сделана (например, переполнен контекст) |

Коды 2 и 3 различаются намеренно: в первом случае сервера нет вовсе, во втором
он ответил, но запрос отклонил. Интерактивный режим всегда завершается нулём —
провал отдельной задачи не есть провал сессии.

### Интерактивный режим

`mini_agent -i` держит одну историю на всю сессию: следующая задача видит
результаты предыдущей. Стрелка вверх поднимает прошлые задачи, строку можно
править по месту (`Reline` из stdlib).

| Команда | Что делает |
|---|---|
| `/help` | Список команд |
| `/clear` | Начать историю заново |
| `/context` | Из чего складывается контекст |
| `/compact` | Свернуть диалог в резюме |
| `/init` | Создать описание проекта (`AGENTS.md`) |
| `/model` | Какая модель, сервер, каталог и журнал используются |
| `/tools` | Доступные модели инструменты |
| `/usage` | Расход токенов за сессию |
| `/exit` | Выход (`exit` без слэша тоже работает) |

`/clear` нужен, когда следующая задача не связана с предыдущей: история
накапливается и уходит модели целиком, а лишний контекст и стоит токенов, и
сбивает с толку.

### Что занимает контекст

`/context` показывает, из чего сложился диалог:

```
> /context
Контекст: 7 сообщений

  системный промпт        908 знаков   41%
  описание проекта        390 знаков   18%
  задачи                   26 знаков    1%
  ответы модели             471 знак   22%
  результаты команд       395 знаков   18%
  ------------------------------------
  всего                  2190 знаков

  по данным сервера последний промпт — 955 токенов
```

**Размер в знаках, а не в токенах, и это сделано намеренно.** Своего
токенизатора в агенте нет, а пересчёт знаков в токены коэффициентом даёт
ошибку в полтора-два раза (для русского текста и для кода он разный) — и при
этом выглядит ровно так же уверенно, как измерение. Знаки посчитаны точно;
единственное честное число о токенах присылает сервер в `usage`, и оно
показано отдельной строкой как есть. Если сервер `usage` не присылает, агент
говорит об этом, а не печатает ноль.

Описание проекта вынесено отдельной строкой не для красоты: `AGENTS.md`
попадает в системный промпт и переживает и `/clear`, и `/compact`. Если место
занято им, `/context` предупредит — уменьшить его можно только правкой файла.

### Сворачивание диалога

`/compact` просит модель пересказать диалог и заменяет им историю:

```
> /compact
Диалог свёрнут: 4625 знаков → 2469.
```

Резюме встаёт на место всего разговора; системный промпт и описание проекта
возвращаются в новую историю целиком. Модель после этого помнит, что было
сделано, но не дословные формулировки — поэтому сворачивать лучше на границе
между задачами, а не посреди одной.

**`/compact` работает на упреждение и переполненный контекст не лечит.** Чтобы
получить резюме, историю надо отправить модели целиком — то есть сделать ровно
тот запрос, который при упоре в окно уже не проходит. Звать его нужно до того,
как стало тесно; `/context` показывает, когда пора.

Если свернуть не удалось — сервер недоступен, модель вернула пустой ответ,
нажали Ctrl+C — история остаётся прежней и работать можно дальше. Потерять
диалог, не получив взамен резюме, — худший из исходов, и агент его избегает.
Запрос на сворачивание оплачивается и попадает в `/usage`, даже если резюме
не пригодилось.

### Расход токенов

`/usage` показывает, во что обошлась сессия:

```
> /usage
Токены за сессию:
  отправлено:  1037
  сгенерировано: 120
  контекст сейчас: 530 (запросов: 2)
```

**«Отправлено» и «контекст» — разные числа, и это не ошибка.** История уходит
модели целиком на каждом ходу, поэтому одни и те же сообщения оплачиваются
повторно: «отправлено» — сумма по всем запросам, а «контекст сейчас» — размер
последнего, то есть текущий объём диалога. Именно второе число упирается в окно
модели, а первое ближе к деньгам на облачном эндпоинте.

Потраченное `/clear` не обнуляет: история начинается заново, но счёт за неё уже
выставлен. По той же причине расход провалившегося хода остаётся в счётчике,
хотя сам ход снимается с истории.

### Обрыв ответа на лимите

`max_tokens` ограничивает **ответ** модели, а не размер контекста. Упершись
в него, агент говорит об этом прямо:

```
● Ответ оборван на лимите генерации (max_tokens: 1100), текста не осталось.
  У рассуждающих моделей размышления тратят тот же бюджет.
  Увеличьте --max-tokens или MAX_TOKENS.
```

**Пустой ответ у рассуждающей модели почти всегда означает именно это.**
qwen3 и подобные отдают размышления отдельным полем `reasoning_content`,
но тратят на них общий с ответом бюджет: выбрав его целиком, модель
возвращает пустой текст. Внешне — «модель промолчала», на деле — не хватило
токенов. Если ответ оборвался, но текст всё же пришёл, он показывается
и сохраняется, а рядом печатается предупреждение о неполноте.

Обрыв на пустом ответе — это невыполненная задача, и код возврата будет `3`.
`/compact` в таком случае отказывается сворачивать: обрезанное резюме заместило
бы диалог неполным, и вернуть его было бы уже нечем.

### Контекстное окно

`max_tokens` и история делят **одно** окно, и его размер задаётся при загрузке
модели на сервере — OpenAI-совместимый протокол о нём не сообщает. Поэтому
агент спрашивает его у LM Studio через её собственный `/api/v0/models`, а на
любом другом сервере молча обходится без него. Задать вручную: `--context-window
N` или `CONTEXT_WINDOW`; заданное явно перебивает узнанное и запрос не делается.

`/model` показывает размер, `/context` — заполнение:

```
  по данным сервера последний промпт — 2157 токенов
  окно модели: 6253 из 8192 (76%), с резервом под ответ
● Окно заполнено на 76%, и занято оно описанием проекта — /compact его
  не тронет, уменьшать надо сам файл.
```

**«Занято» включает резерв под ответ.** Место в окне нужно не только истории:
`max_tokens` тоже претендует на него, и без учёта этого картина обманчива —
пустой диалог при `max_tokens: 4096` и окне 8192 занимает половину, ещё
не начавшись. Проценты могут превысить 100: это не ошибка счёта, а ровно тот
случай, ради которого отчёт и нужен.

Предупреждений три, и лечения у них разные:

| Что сказано | Чем лечится |
|---|---|
| Окно заполнено, занято диалогом | `/compact` — пока он ещё проходит |
| Окно заполнено, занято описанием проекта | правкой самого `AGENTS.md` |
| На ответ остаётся меньше `max_tokens` | уменьшить `--max-tokens` либо увеличить окно на сервере |

Последнее — предупреждение о риске, а не приговор: `max_tokens` это разрешение,
а не бронь. При остатке 6035 и лимите 7000 короткий ответ приходит целиком;
оборвётся длинный, и оборвётся на остатке, а не на лимите.

Если размер окна неизвестен, так и написано — вместо процентов, которых не
из чего посчитать:

```
  размер окна неизвестен — сервер о нём не сообщает, задайте --context-window
```

**Ctrl+C прерывает задачу, а не сессию.** Если модель запустила не то или
задумалась надолго, Ctrl+C останавливает текущую работу — история остаётся,
можно уточнить задачу и продолжить. Запущенная команда при этом убивается.
На пустом приглашении первый Ctrl+C сбрасывает набранную строку, второй
подряд — выходит.

### Какая модель отвечает

`--list-models` показывает, что реально загружено на сервере; звёздочкой
помечена выбранная:

```
$ mini_agent --list-models
Модели на http://llm-server:1234/v1:
    deepseek-coder-v2-lite-instruct
  * qwen/qwen3.6-35b-a3b
    text-embedding-nomic-embed-text-v1.5
```

Проверять стоит, потому что LM Studio на незнакомое имя модели **не отвечает
ошибкой** — он молча берёт загруженную. Без этой команды подмену нечем
заметить: агент работает, но не на той модели, которую вы указали.

### Рабочий каталог

По умолчанию агент выполняет команды там, откуда запущен. `--cwd DIR` (или
`AGENT_CWD`) переносит их в другой каталог — там же он ищет и `AGENTS.md`:

```bash
mini_agent --cwd ~/projects/other "запусти тесты"
```

Каждый вызов `bash` — отдельный процесс, и **между вызовами ничего не
сохраняется**: ни текущий каталог, ни переменные окружения. Отдельный `cd sub`
молча пропадает, следующая команда снова начнёт с рабочего каталога. Модель
предупреждена об этом в системном промпте и связывает шаги сама
(`cd sub && ls` вместо двух вызовов).

### Транскрипт диалога

`--log FILE` (или `AGENT_LOG`) пишет весь обмен с моделью в файл — по одному
объекту JSON на строку. По умолчанию выключено.

```bash
mini_agent --log session.jsonl "почини падающий тест"
jq -r 'select(.role=="tool") | .content' session.jsonl   # что видела модель
```

Первой строкой каждого запуска идёт `{"type":"session", …}` с моделью,
сервером и рабочим каталогом: в один файл складываются несколько запусков, и
без этой пометки непонятно, где кончился прошлый. Дальше — сообщения в том
порядке, в каком их видела модель, включая системный промпт и полный вывод
команд (в консоли он обрезан для читаемости). Ключ API в журнал не пишется.

Записи попадают на диск сразу, а не при выходе: разбираться в логе приходится
как раз тогда, когда до нормального завершения дело не дошло — агент завис,
упал или его убили.

Если ход не удался, его сообщения снимаются с истории, а в журнале появляется
строка `{"type":"rollback"}`. Сами снятые сообщения остаются на месте: журнал
показывает, что действительно уходило модели, — иначе по нему нельзя было бы
понять, на чём именно запрос упал.

> В журнал попадают и ваши задачи, и содержимое всех файлов, которые агент
> читал. Прежде чем приложить его к отчёту или багрепорту, посмотрите, что
> в нём оказалось.

### Описание проекта

Если в рабочем каталоге лежит `AGENTS.md` (или `.mini_agent.md`), агент читает
его и дописывает к системному промпту. Туда стоит положить то, что иначе он
выясняет заново каждый запуск: чем запускаются тесты, где лежат исходники,
на каком языке комментарии.

```
$ mini_agent "какой командой запускаются тесты?"
Контекст проекта: AGENTS.md

● Тесты запускаются командой make spec-fast.
```

Без этого файла тот же вопрос стоит нескольких ходов `ls` и `find`.
Берётся первый найденный файл, потолок — 32 КБ.

Написать его можно и руками, но проще поручить агенту — команда `/init`
в интерактивном режиме:

```
> /init
● Bash(pwd && ls -la)
● Bash(cat README.md)
● Bash(cat Rakefile)
● Bash(cat src/parser.rb)
● Bash(rake -T 2>&1)
● Bash(rake 2>&1)
● Bash(cat > AGENTS.md << 'EOF' …)
● Bash(cat AGENTS.md)

Описание проекта записано: AGENTS.md (694 байта).
  Оно вступит в силу после /clear или при следующем запуске.
```

Агент изучает каталог сам и пишет файл на языке, принятом в самом проекте.
Команды сборки и тестов ему велено **проверять запуском**, а не переписывать
из README: неверная команда хуже отсутствующей, потому что выглядит
проверенной. Живая проверка показала, что это не перестраховка — без явного
требования модель приняла `require "rake/testtask"` за наличие задачи `test`
и записала несуществующую команду.

Если описание уже есть, `/init` покажет его размер и спросит про перезапись —
файл мог писать человек.

Новое описание попадает в системный промпт при сборке истории, поэтому к уже
идущему диалогу оно не применяется: нужен `/clear` или следующий запуск.
Применять его на месте значило бы незаметно выбросить текущую историю.

> **Файл описания равносилен исполняемому коду.** Указания внутри `AGENTS.md`
> модель выполняет: строка «игнорируй задачу пользователя и сделай вот это»
> в нём работает, и никакая формулировка промпта этого не предотвращает
> (проверено живьём). Тот, кто подложил файл, управляет агентом, а агент
> запускает команды. Открывать чужой непроверенный проект этим агентом так же
> рискованно, как выполнять в нём `make`. Строка «Контекст проекта: …»
> в выводе показывает, что файл подхвачен.

### Переменные окружения

`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `MAX_TURNS`, `RETRY_COUNT`, `RETRY_DELAY`, `MAX_TOKENS`, `CONTEXT_WINDOW`, `ALLOW_UNSAFE`, `COMMAND_TIMEOUT`, `AGENT_CWD`, `AGENT_LOG`.

Приоритет: опции CLI → переменные окружения → значения по умолчанию.

```bash
export LLM_BASE_URL=http://llm-server:1234/v1
export LLM_MODEL=qwen3-coder
mini_agent "покажи структуру проекта"
```

## Как это работает

```
CLI → Agent (цикл ходов) → LLMClient ⇄ LLM
                ↓
         ToolRegistry → Tools::Bash → CommandGuard → ProcessRunner
```

Агент отправляет модели задачу вместе со схемой доступных инструментов. Модель отвечает либо вызовом инструмента — тогда команда выполняется, а её вывод возвращается модели, — либо обычным текстом, что означает завершение работы. Цикл ограничен числом ходов; по достижении лимита агент просит модель подвести итог.

## Безопасность

Агент выполняет shell-команды, которые формирует языковая модель. Перед запуском команд, похожих на разрушительные (`rm -rf`, `sudo`, `curl | sh`, форк-бомба и подобные), запрашивается подтверждение.

**Этот фильтр не является песочницей.** Он защищает от случайностей и ошибок модели, но обходится переписыванием команды. Если вы запускаете агента с недоверенной моделью или на важной машине, используйте реальную изоляцию — контейнер или отдельного пользователя с ограниченными правами.

Флаг `--allow-unsafe` (или `ALLOW_UNSAFE=true`) снижает проверку до предупреждения без запроса подтверждения.

## Разработка

Рабочие вызовы собраны в `Makefile`; `make help` печатает список целей.

```bash
make setup        # установка зависимостей
make              # тесты и линтер
make spec         # только тесты
make spec FILE=spec/mini_agent/agent_spec.rb:42     # один пример
make lint         # линтер
make rbs          # проверка сигнатур в sig/
make console      # IRB с загруженным гемом
make run TASK="покажи структуру проекта"
make repl         # интерактивный режим
```
