## [Unreleased]

### Добавлено

- GitHub Actions: тесты, линтер и `rbs validate` на Ruby 3.3 и 3.4 при пуше и PR в `master`. Шаги вызывают цели `Makefile`, чтобы CI проверял ровно то же, что разработчик локально.
- `ErrorResponse` — разбор неуспешного ответа LLM-сервера: повторять ли запрос, сколько ждать и что показать человеку. Вынесен из `LLMClient` отдельным классом: разбор чужого формата ошибок — своя задача со своими краевыми случаями, и в клиенте она тонула среди логики повторов.
- Поддержка заголовка `Retry-After` при HTTP 429: сервер знает, когда освободится, и его значение перебивает настроенную `retry_delay`. Потолок — 60 секунд (агент интерактивный, долгое молчание неотличимо от зависания); форма HTTP-даты игнорируется, поддержана только числовая.
- Опция `--list-models`: список моделей, загруженных на сервере, с пометкой выбранной. Нужна потому, что LM Studio на незнакомое имя модели не отвечает ошибкой — он молча подставляет загруженную, и без этой команды подмену нечем заметить.
- `ModelsRequest` — запрос `GET /models`. Отдельно от `LLMClient` намеренно: тот ведёт диалог (держит соединение, повторяет запросы, разбирает `choices`), а здесь разовая справочная команда без повторов — человек смотрит в терминал, и молчаливое ожидание перед показом ошибки хуже самой ошибки.
- Описание проекта из `AGENTS.md` (или `.mini_agent.md`) в рабочем каталоге дописывается к системному промпту. Без него агент выясняет устройство проекта заново на каждом запуске: живая проверка на пустом каталоге — `ls`, развесистый `find` и упор в лимит ходов там, где с файлом ответ приходит сразу и без единой команды. Берётся первый найденный файл, потолок — 32 КБ. О подхваченном файле сообщается строкой «Контекст проекта: …»: молчаливое изменение поведения агента хуже лишней строки в выводе.
- `docs/ROADMAP.md` — план развития, упорядоченный по сложности.

### Изменено

- Неуспешные HTTP-коды разделены на повторяемые и окончательные. Раньше любой не-`HTTPSuccess` уходил на повтор, и HTTP 400 «пустая история сообщений» стоил трёх запросов и шести секунд ожидания перед неизбежной ошибкой. Теперь повторяются только 5xx, 408 и 429, остальные 4xx падают сразу: живая проверка на LM Studio — 0,27 с вместо 6,3 с.
- Текст ошибки сервера берётся из поля `error.message` тела ответа, а не показывается сырым JSON. Поддержаны три встречающиеся формы: `{"error": {"message": "…"}}`, `{"error": "строка"}` и произвольный текст.

- Минимальная версия Ruby поднята с 3.1 до 3.3 (`required_ruby_version`, `TargetRubyVersion`). Заявленная поддержка 3.1 была нерабочей: dev-зависимости из `Gemfile.lock` не встают ниже 3.3 (`parallel 2.1.0` тянется через `rubocop`, плюс `rbs`, `rdoc`, `erb`, `public_suffix`), и `bundle install` падал до запуска тестов.
- В `Gemfile.lock` добавлена платформа `x86_64-linux` — без неё `bundle install` в CI падает на отсутствующей платформе.

### Исправлено

- Ссылки на репозиторий вели на несуществующий `s-golovko/mini_agent` (404). Верный адрес — `GolovkoStepan/mini_agent`; из него же строятся `source_code_uri` и `changelog_uri` в гемспеке.

- Адрес LLM по умолчанию — `http://llm-server:1234/v1` вместо конкретного IP локальной сети. Имя прописывается в `/etc/hosts` (см. README): сервер обычно стоит на отдельной машине, а IP в репозитории бесполезен всем, кроме автора.
- `Color.gray` переведён с `\e[90m` (bright black) на `\e[38;5;245m`. Тёмные темы терминала маппят bright black почти в чёрный, и вывод инструментов становился нечитаемым; 256-цветный серый не зависит от палитры темы.

## [0.2.0] - 2026-07-31

### Добавлено

- Исполняемый файл `exe/mini_agent`; новые опции `--base-url`, `--model`, `--version`.
- `Makefile` с целями разработки (`make help` — список): проверки, запуск агента, сборка и установка гема.
- Тесты RSpec (164 примера); HTTP стабится через webmock, живой LLM не требуется.
- Настройка таймаута команды через `COMMAND_TIMEOUT` (по умолчанию прежние 120 секунд).

### Изменено

- Монолитный скрипт `agent.rb` разобран на классы в `lib/mini_agent/`: `Agent`, `LLMClient`, `Conversation`, `ToolRegistry`, `Tools::Bash`, `CommandGuard`, `ProcessRunner`, `Prompt`, `UI`, `Config`, `Messages`, `Color`.
- Единый приоритет настроек: опции CLI → переменные окружения → значения по умолчанию. Раньше `base_url`, `api_key` и `model` читались только из окружения и игнорировали переданные опции.
- Раскраска вывода переведена с refinement на обычный модуль `Color`.
- Консольный вывод переработан: события помечаются маркером `●`, вывод инструмента уходит под `⎿` с отступом. Убраны баннер `═══ Ход N ═══` (номер хода теперь виден только в спиннере), рамки вокруг вывода и эмодзи. Предпросмотр вывода сокращён с 10 строк до 5, код возврата показывается только при ошибке.
- `Messages` разделён на слой терминала и вложенный `Messages::Tool` — строки, уходящие результатом инструмента в модель.
- `Color.gray` исправлен с `\e[37m` (обычный белый, неотличим от текста на светлой теме) на `\e[90m`; добавлен `dim`.
- Название в заголовках интерфейса приведено к «Mini Agent» (было «Coding Agent»).

### Исправлено

- Пустая строка в блоке вывода инструмента, когда команда писала только в stderr: ведущий перевод строки нужен модели как разделитель секций, но на экране был лишним.
- Недоступный LLM-сервер валил агента сырым бэктрейсом `Net::OpenTimeout` («Failed to open TCP connection…»). Теперь показывается адрес, причина и подсказка про `--base-url`/`LLM_BASE_URL`, код возврата — 2. Отдельно разбирается случай нечитаемого адреса.
- Флаг `--no-allow-unsafe` не мог перебить `ALLOW_UNSAFE=true`.
- Объект HTTP-запроса переиспользовался между повторными попытками обращения к LLM.
- В суммирующем запросе при достижении лимита ходов модели больше не предлагаются инструменты (`tool_choice: "none"`) — раньше возвращённые ею вызовы молча терялись.
- Вызов агента без предварительного открытия соединения падал с `NoMethodError`; соединение поднимается лениво.
- Ключи сообщений в истории приведены к единому виду (символы вместо смеси символов и строк).
- Пустая команда больше не запускает пустой shell, а возвращает понятную ошибку.
- Уточнён список опасных команд: убран неработавший шаблон, добавлены `wget | sh`, `doas`, `shutdown`/`reboot`, перезапись блочных устройств.
- Использование `Timeout::Error` без `require "timeout"` заменено на собственный `MiniAgent::TimeoutError`.
- По достижении лимита ходов просьба подвести итог отправляется ролью `user`, а не `system`: шаблоны чата Qwen и ряда других моделей принимают `system` только первым сообщением и отвечали HTTP 400.
- Тело ответа с ошибкой перекодируется в UTF-8: `Net::HTTP` отдаёт его как ASCII-8BIT, и склейка с русским текстом сообщения роняла клиент `Encoding::CompatibilityError` вместо показа самой ошибки сервера.
